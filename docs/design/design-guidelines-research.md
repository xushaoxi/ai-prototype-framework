# 设计指南结构与实践研究

研究日期：2026-10-26。状态：外部研究及适配建议，尚未作为框架验收规则，不代表完成用户研究或界面验证。

## 范围与结论

跨站检索并查阅 Ant Design、IBM Carbon、Atlassian、Microsoft Fluent、GOV.UK 与 W3C 的公开官方资料。选取与中文企业业务原型相关的内容；这不是穷尽全网，也不存在经统一评测产生的“全球最佳指南”。下文的最佳实践指成熟来源支持、可解释并可验证的候选做法。

完整指南需要覆盖设计原则、视觉基础、组件使用、业务任务模式、系统状态、内容、可访问性与维护验证。完整的是决策覆盖范围，不要求一次实现所有组件或页面。

当前框架为 React + Ant Design 的 T01 台账原型。已有颜色、字号、间距、弹层尺寸等视觉基线，已有规范与测试机制；设计决策指南刚起步。以下适配判断基于 README、架构、设计文档及已读取的统计区代码，未对全部页面进行视觉或交互审计。

## 三、优先评估的实践

以下均为候选规则，逐条讨论后才能转入正式指南。

1. **以任务决定信息层级。** 查询列表优先支持定位、比较和操作；概览指标必须说明额外业务价值。数字卡片默认省略是本项目的适配建议，并非上述设计系统的统一强制规定。依据：Ant Design 数据展示与设计价值、Fluent 设计原则。
2. **按需提供表格能力。** 根据实际任务选择搜索、排序、分页、选择与批量操作；无需在模板里默认展示所有能力。依据：Carbon 数据表格。
3. **明确筛选的生效方式。** 简单、快速返回的筛选可即时生效；多条件组合或慢响应可集中点击查询。隐藏条件仍要能识别和清除。依据：Carbon 筛选。
4. **按任务复杂度组织表单。** 简单快速操作可用轻量容器；长表单、跨组依赖和多步骤任务需要更多空间与结构。不能只凭字段数量决定弹窗或抽屉。依据：Ant Design 表单页；容器判断是本项目的进一步建议。
5. **区别“没有”与“没找到”。** 首次无记录引导新增；筛选无结果引导调整条件；请求失败说明如何重试。依据：Carbon 空状态。
6. **文案说明结果与下一步。** 使用一致业务术语和明确动作；错误消息给出可执行的修复方向；日期、单位和统计范围明确。依据：Atlassian 内容指南。
7. **紧凑不能牺牲操作能力。** 表格密度是任务选择；紧凑控件仍需检查键盘、焦点与点击区域。WCAG 2.2 AA 的指针目标最低尺寸条件为 24×24 CSS px，也存在间距等例外，不能简化为所有按钮必须可见地画成 24px。依据：[目标尺寸解释](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)。
8. **浮层与固定区域不得遮住操作位置。** 弹层管理焦点；固定头部、底部与提示区域需检查是否完全遮挡获得焦点的控件。依据：[焦点不被遮挡解释](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum)。
9. **新规则带证据进入。** 从实际问题提出，记录适用范围、正反例及检查方法；外部实践标记来源，本地建议与验证结果分别记录。依据：GOV.UK 贡献准则与使用指南。

## 四、推荐的适配策略

采用“Ant Design 作为实现基础 + Carbon 补充数据密集交互 + Atlassian 补充内容 + WCAG 提供可测试底线 + GOV.UK 借鉴规则维护方法”的组合。Fluent 用于校验聚焦任务和跨设备原则。此组合是研究后的建议，不涉及安装新组件库。

暂不扩展：真实认证与服务端授权、完整审批引擎、复杂分析仪表盘、嵌套业务编辑器、全品牌资产体系、多语言运行时。相应章节可以记录边界，出现真实业务需求后再展开。

现有视觉基线中的 11px 辅助字、12px 密集表格字和当前卡片布局，后续需要结合可读性、对比度、缩放与首屏信息评估，不能因为已写进文档便视为验证通过。

## 五、逐项讨论方式

每次选一个问题，按下列顺序走完，再处理下一条：

1. 当前用户任务与具体问题。
2. 外部实践及其适用条件。
3. 本框架的约束和可选方案。
4. 默认规则与允许的例外。
5. 正反例、检查方法及验证结果。
6. 确认后同步正式指南、相关基线与实现。

建议先评估：页面任务与数字卡片 → 查询生效与筛选范围 → 表格列及操作 → 表单容器 → 状态反馈。可访问性和小屏要求随每项一起检查。
