# 原型工作台建设方案：设计指南与可复用模式

日期：2026-10-29。
状态：建设方案与目标清单；经多角色对抗审查后修订，仍不是当前界面已完成或已验收的声明。本轮仅整理方案，不修改运行界面。审查依据见[对抗审查记录](prototype-workbench-adversarial-review.md)。

## 1. 目标与定位

需求明确后，设计者或AI能匹配页面结构、组合组件、基础组件和交互规则，绘制风格一致、行为可演示的后台原型。交付物包括文字指南、视觉规范、可操作示例、类型化复用接口及需求到验收的映射。

用户已确认核心使用方式：把需求交给AI，由AI按指南和共享组件生成可运行原型。工作台同时服务于人的浏览、试用与对照，以及AI的规则检索、结构选择和代码复用。本方案不因此建设整套拖拽生成器；自定义工作台、配置向导是被展示和复用的页面模式。

工作台是原型设计工具和模式参考，不是虚构业务后台。业务名称、字段及数据仅解释模式；不能靠换业务名增加模板数量。完整性以结构、能力、状态及复用验证衡量，不以页面数或测试数单独衡量。

原则：一种基础结构一个入口；不同能力在入口内部切换；业务只作为示例数据。真实后端、认证、权限、文件存储、财务支付、工作流引擎不属于原型基础库。

## 2. 四层内容与关系

| 层级 | 回答的问题 | 产物 |
| --- | --- | --- |
| 设计规则与视觉基础 | 为什么选它、怎么保持一致 | 选型规则、视觉变量、状态与格式规范 |
| 基础组件 | 用哪些基本控件 | 有名称、帮助、状态及尺寸的组件示例 |
| 组合组件 | 如何完成一段可复用交互 | 筛选区、对象选择器、明细编辑、状态处理等 |
| 页面结构 | 整个任务如何组织 | 查询、表单、详情、阶段、排程、关系、分析、配置等 |

项目中的用户、合同、审批、设置等是业务任务，不直接成为本工作台的模式分类。流程图表现业务过程也不等于提供流程引擎。

## 3. 设计指南应规定的内容

1. 需求输入：角色、核心任务、对象、事件顺序、字段来源、可修改时机、状态动作、数据量、使用频率和设备。
2. 结构选型：按查找、录入、理解对象、推进过程、排程、分析、配置等任务选结构，说明适用及不适用条件。
3. 信息架构：模块/页面/页签/分区的区别，主要操作归属，深链接、返回现场，层级与重复标题控制。
4. 视觉基础：唯一主题来源；颜色、字体、字号行高、间距、边线、圆角、阴影、图标、层级、控件尺寸、布局网格。
5. 基础组件：语义、选型、尺寸、帮助、默认值、状态、键盘和组合方式。
6. 页面与组合模式：本方案第4、5节；每种给出默认版、变体、完整交互及可复用接口。
7. 数据与文案：金额/单位/精度、日期时间、空/未知/零、状态、动作、错误与确认文案。
8. 状态与恢复：初次加载/刷新/空/错误/只读/禁用/校验/并发/未保存/危险操作。
9. 响应与可访问性：内容区宽度、局部滚动、焦点、键盘、非颜色提示、文字缩放、减少动态。
10. 原型数据与演示：数据来源、确定性样本、演示角色、可重置范围和仿真边界。
11. 复用接入：需求映射表、模块或服务适配点；公共组件与特殊业务扩展的边界。
12. 规则维护和验收：规则ID、依据、例外、实现状态、验证状态、对应组件/测试/截图；实际结果与计划分开。

既有16章大纲可保留作详细目录，补全上述内容；不因改版再维护第二份相互冲突的规则正文。

## 4. 页面结构：九个模式族

九族是当前任务导向的检索入口，不是互斥分类，也不代表九套独立业务模型。每个入口须说明主任务、完成结果、适用与不适用条件；使用时先选择主体结构，再组合能力。无法合理归类的需求允许显式扩展，不能硬塞进九族或只凭业务名称新增模式。

### P01 查询与列表

解决查找、比较、选择和处理一组记录。默认复用已定版PAGE-003，资产/供应商只是可切换样例。

展示：标准查询表格；表格/树表/卡片集合；树导航+内容；列表+详情主从。树导航选分类后右侧得到一组对象；主从选择一条记录后右侧得到该对象信息，必须解释区别。

能力变体：更多筛选、状态计数、列显示/宽度/顺序/固定、排序分页、批量选择、跨页范围、行内编辑、展开行、导出。按需开启，默认版不堆满能力。不再另设资产、供应商、高级表格、待办等重复入口。

### P02 表单录入

解决新增/编辑对象；新增与编辑共用结构，区别为初值、字段权限和动作。展示基础、分组、分步、联动、主子/明细、重复项录入及只读回显。

完整页面延续已确认的桌面三列，内容区变窄降两列/一列；备注、附件及明细可跨整行。弹窗/抽屉按可用宽度匹配列数，不机械复用完整页尺寸。提供金额与数量、日期时间、对象选择、条件必填、附件、草稿和提交校验组合。

### P03 详情展示

解决理解和处理一个对象。展示简单详情、多分组详情、完整多页签详情；页首对象身份、状态及主操作，主体平级页签/分区，辅助记录或关联对象在抽屉查看。

关键组合：概览摘要、关键指标、主子明细、关联对象、附件、业务历程、操作记录；概览能定位详细来源。区分业务历程与系统审计；支持返回保留对象/页签/筛选/滚动，不靠多层抽屉拼全貌。

### P04 阶段过程跟踪

参考集团项目商机和签约过程：阶段导航+阶段内容/进展，包含责任人、计划/实际时间、停留/逾期、记录、附件、推进或重开。

展示横向阶段条与左右阶段布局；未开始/进行/完成/阻塞/超期；更新进展与查看历史。阶段变更要遵守源规则。它不是待办表格，也不是将审批通过/驳回换标签。

### P05 任务与时间排程

展示WBS层级、甘特、里程碑、人员排期和日历，解释各视图用途。层级任务、时间事件、资源占用分别声明必要输入和操作约束；语义兼容时使用同一组数据切换视图，不强制共用一个业务模型。

WBS：阶段/任务/子任务、增删及汇总边界；甘特：任务与时间轴、计划/实际对比、进度与里程碑；人员排期：人员×时间、多任务分层与冲突；日历：月/周/日或日期+事件明细。视图选择和选中任务尽量共用现场，不伪称具有未实现的拖拽调度算法。

### P06 关系图谱

参考集团项目关系全景：不同类型节点、关系边和标签，查看节点/边信息，展开收起、搜索定位、平移缩放、小地图与全屏。

展示简单对象关联、层级关系、多对象业务链。区分查看、布局调整和实际维护关系；拖动画布节点不自动更改业务关系。点击打开对象/关系侧栏，返回保留视角。

### P07 指标分析

解决概况、趋势、对比、结构、排行和异常定位。展示指标卡、条/柱图、折线图、占比、漏斗、排行及明细联动。

每个指标有范围、时间、单位、口径和缺失含义；点击按同口径下钻，不只改变数字。查询列表不默认复制一排指标卡。原项目“商机看板”属于此模式，不按名称误归拖拽卡片看板。需要状态分列拖动的业务另作为集合展示变体定义，不凭名字添加。

### P08 自定义工作台

区别于固定驾驶舱：从组件库添加多个组件实例，配置范围/字段/条数，移动、调整尺寸、自动排版、移除、撤销、保存/取消和恢复布局。

预览/编辑态分开；布局只存配置、不复制源业务事实。组件有最小尺寸与异常恢复；一个组件失败不影响其他组件。保存/取消以整份布局草稿为单位，不能演示了拖动却没有真正取消恢复。

### P09 配置向导

参考报表设计器：选择主题/对象→选字段并调整顺序/别名→配置条件→预览→保存配置/导出。

可扩展到导入映射、模板配置与简单规则条件。配置数据、业务数据和临时查询结果分离。展示条件行、运算符、不同类型值、增删排序、校验与保存。报表配置与导入映射是不同变体，不等同于无限低代码设计器。

## 5. 应提供的组合组件

| 编号 | 组合 | 必须展示的内容 |
| --- | --- | --- |
| C01 | 查询筛选区 | 常用/更多条件、按钮/Enter、已生效与未提交、重置、条件范围 |
| C02 | 数据表格 | 列偏好、长文本、选择/批量范围、行操作、合计和导出 |
| C03 | 对象选择与关联 | 人员/部门/业务对象，搜索单多选、已选区、回显、关联角色/范围及移除 |
| C04 | 动态明细编辑 | 增删行、类型校验、计算/合计、顺序与只读，主表与明细一次提交 |
| C05 | 金额/比例分配 | 可分配值、已分配、余额、单行与总量上限、确认与更正；金额不是业务付款 |
| C06 | 阶段与处理面板 | 阶段/状态、负责人、期限、意见、处理动作、历史与不可操作原因 |
| C07 | 业务历程 | 时间、阶段、事件、责任与来源，关联对象跳转；与操作日志分开 |
| C08 | 附件与证据 | 列表、限制、选择/上传/失败状态、预览/下载/移除的仿真或真实边界 |
| C09 | 导入导出 | 文件/模板、字段映射、校验错误行、范围/列选择、结果及恢复 |
| C10 | 指标与下钻 | 指标/图表、口径说明、点击后同条件明细与返回 |
| C11 | 树/权限矩阵选择 | 搜索、单多选、全/半选、层级/依赖、已选及保存；不做系统管理业务页 |
| C12 | 布局编辑 | 组件实例、配置、移动缩放、撤销、自动排版与保存取消 |

待办=列表+状态/责任筛选+处理入口；审批=对象信息+意见/动作+记录；回收站=列表+恢复/永久删除；设置=分组表单。它们用于解释组合，不能据此扩出一批重复业务菜单。

## 6. 基础组件展示范围

- 布局：网格、间距、分割、卡片、分区/分隔面板、固定区与滚动区。
- 导航：菜单、功能标签、内容页签、面包屑、锚点、步骤、分页。
- 操作：主/次/文字/图标按钮、下拉/更多、危险与批量操作。
- 输入：文本/多行/搜索/密码/补全、数量/金额/百分比/单位、日期/时间/日期时间及范围。
- 选择：单选/复选、下拉单多选、开关、树/级联、穿梭、滑块；评分/颜色等标明低频选用条件。
- 展示：表格/树/卡片/描述列表、标签/徽标/头像、时间轴、进度、图片预览和文本省略。
- 容器：弹窗、抽屉、完整页面、Popover、Tooltip、折叠面板；展示选择条件、尺寸、滚动、焦点、底部操作。
- 反馈：消息/通知/Alert、加载/骨架、初始空/筛选空、成功/失败/无权限/不存在、重试/恢复。
- 扩展：富文本/代码编辑、大数据虚拟化、地图等按确有需求扩展；不通过无依据安装所有依赖来宣称完整。

每个示例有可操作状态与使用说明；直接复用既有Ant Design公开API，不再包装一层没有增益的同名基础组件。

## 7. 全部模式共同遵守的规则

- 正常/首次加载/局部刷新/空/筛选空/失败重试；适用时有只读、禁用及原因。
- 新增/编辑回显、必填/格式、FORM-007首次提交与修正反馈、错误定位、失败保留输入。
- FORM-008取消/关闭/返回/后台标签与刷新，切换现场和未保存/草稿区别；保存期间防重复及关闭。
- 危险确认说明对象与后果，默认安全焦点；按风险决定确认或撤销，不到处堆确认弹窗。
- 版本冲突、数据过期和持久化失败有真实恢复路径，不以toast冒充保存。
- 数字/金额/日期/时区/单位一致，空、未知、零分开；长内容完整可达。
- 桌面/窄屏/手机按可用宽度变形；局部滚动、键盘、焦点、非颜色语义及减少动态。
- 示例数据可重置，身份、权限、附件、通知等仿真明确，但不把开发说明塞满原型画布。

跨页组合还须约定来源条件、对象身份、返回落点、未保存处理、提交后的更新及焦点恢复。至少用“列表→详情→关联对象→编辑→返回”和“录入→创建关联对象→回填”验证；直接访问无来源的页面也有有效返回路径。沿用现有现场机制，不为此新增流程引擎。

## 8. 如何保持产品风格一致

1. 沿用已确认的当前主题，集团项目平台用于提炼结构和交互，不直接混入另一套蓝色/深色侧栏主题。新品牌项目从统一主题入口换肤，不逐页手改。
2. 主题与视觉变量应单一来源，覆盖颜色/字体/间距/圆角/边线/阴影/图标/尺寸/层级；明确基础值、语义token、组件规则的映射，Ant主题与自定义CSS共同消费。列出存量迁移范围和允许例外；不能宣称目前已全部收口。
3. 页面和组合组件共享实现，变体通过有限明确接口选择；公共规则不由各业务页面重写。
4. PAGE-003、查询每行最多三个条件、点击/Enter查询、导出右侧图标列设置、完整表单三列等已确认规则保留，除非明确变更。
5. 每次交付对照代表性页面和状态检查截图、布局、文案与交互；自动测试不代替产品结构和视觉评审。

## 9. 工作台展示方式与菜单

左侧使用不折叠分组，各入口平铺：

- 规范与基础：设计指南、视觉基础、基础组件、布局与容器。
- 页面结构：查询与列表、表单录入、详情展示、阶段过程、任务与排程、关系图谱、指标分析、自定义工作台、配置向导。
- 组合与反馈：组合组件、交互与状态。

每个入口内展示默认示例、结构/能力变体、适用规则和必要状态。不是把每个组件再做成一级菜单，也不在工作台里复制组织用户等业务系统导航。

工作台工具区与原型展示区分开：变体/尺寸/状态切换、样例数据、规则对照属于外壳；原型区域展示业务界面的真实布局。仿真标记和数据维护集中设置，不在每个模板主体重复长说明/备份/重置工具栏。桌面支持规则与原型并排，窄屏用抽屉；参考入口不独占一行或重复页面名称。

## 10. 现有内容如何处理

| 现有内容 | 整理方式 |
| --- | --- |
| 资产/供应商台账 | 查询与列表内的样例切换；供应商保留为复用验证，不占独立业务菜单 |
| 高级表格 | 并入表格能力变体；提取与标准查询共用组件，默认版不膨胀 |
| 待办/审批/消息/日志/回收站 | 提取列表、状态处理、时间记录与恢复能力，退出主要业务菜单 |
| 组织/用户/角色/系统设置/个人资料/登录 | 移出主要展示菜单；树选择、对象选择、权限矩阵、分组编辑等能力提取复用 |
| 基础/分组/分步/明细/草稿 | 收到表单录入内部；草稿作为保存能力，不单建业务模块 |
| 简单详情/主从/关系等已有示例 | 按真实结构归位；薄弱部分以集团项目平台的实际模式补强 |
| 仪表盘 | 归入指标分析；固定分析与可配置工作台严格区分 |
| 导入/文件 | 归入对应组合与配置向导，保留端到端演示 |
| 已有数据与代码 | 先做覆盖映射再合并；保留必要兼容与复用验证，不直接清空用户数据或整库推倒 |

## 11. 需求明确后的使用流程

主要执行者是AI，使用者提交业务需求并审阅原型。应提供单一接入索引，指向适用规则、共享组件出口、扩展接口和最小实例，避免每次从散落示例重新推断用法。下列为目标使用契约，不宣称目前所有模式已有稳定公共接口。

1. 需求→任务和数据：对象/角色/事件/字段来源/状态/动作/口径/数据量/设备。
2. 任务→结构：输出页面清单，优先选择P01–P09中的主体结构并组合能力；注明选择依据、相邻结构不适用原因及必要扩展。
3. 结构→组件：对应C01–C12与基础控件，确定主次信息、容器、分组和变体。
4. 组件→规则：引用主题、PAGE/FORM/QUERY等规则，明确默认和业务例外。
5. 原型→数据闭环：首次维护→保存→列表/详情一致→后续更新→可查询定位→异常恢复。
6. 预览→交付：提供可运行页面、启动方式、业务规范与需求映射，以及产品结构、样式、交互、响应和数据规则的实际验证证据。交付只包含选定业务内容及必要仿真入口，不夹带无关样例、指南导航或工作台维护工具；独立项目与工作台内预览共用主题和页面实现。

每个新项目先形成一张映射表：需求/页面/结构ID/组合ID/字段与动作/容器/规则ID/例外/验收。不是再次凭感觉选择布局。

接入验证须实际走完“给AI一份需求→读取索引→选型→复用或显式扩展→运行预览→交付”的全过程，记录是否修改共享容器、复制整页、补造无关字段或添加逐页样式。项目创建沿用已有安全脚本，不将这个流程自动扩大为新的生成平台；项目存放方式按实际交付要求选择。

## 12. 完成标准与实施批次

单项只有规则说明、可操作示例、共享实现/类型化接口、必要状态、响应键盘检查和复用示例齐全，才可标为可复用；实现和验证分别记录。核心结构至少用两种不同字段/数据结构验证复用，不通过复制业务整页证明。

建立模式/组合的能力清单：必要操作、适用状态、不适用及理由、仿真边界、共享出口、验收及证据；区分计划、可演示、可复用、已验证。覆盖证据与跨项目复用证据分别记录，不机械地给每个变体凑两套业务。复杂图形操作提供可执行的键盘或按钮等价路径。明确本批范围，整体覆盖目标保留，未完成项不得提前算作完成。

- A 收敛：落实AI接入契约，按真实结构重组导航，合并重复页面，主要展示去业务化；保留标准查询基准。选定一份来自参考项目和一份结构不同的独立需求作验证；没有真实第二份需求时使用明确标注的合成场景。
- B 纵向验证与固化：先用差异化需求跑通主题、核心容器和跨页闭环，再提取实际需要的类型化内容插槽与回调。统一基础组件、组合组件及全局交互；旧业务快照只作样例适配，不成为所有新项目的必需依赖。
- C 补强：复杂详情/阶段跟踪/WBS与时间视图/关系图/自定义工作台/配置向导，以集团项目实际模式为参考。
- D 覆盖与交付验收：核对各项承诺的能力及状态；复核两组不同需求的完整原型，验证不复制整页、不逐页改样式、无关示例不混入交付；同步指南和实际交付证据。复用验证贯穿前述批次，而非最后才开始。

此处顺序是整体实施顺序，不要求用户逐条确认。测试全绿只证明所测行为，不能单独证明模式完整或设计合理；未经实现与验证不得把本方案当完成报告。
