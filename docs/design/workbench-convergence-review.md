# 本轮最终只读复核

范围：工作台目录/recipes、主题与CSS、AllocationEditor、复杂结构共享组件与适配页、structureStore/API/MSW及新增测试和状态说明。依据AGENTS、收敛计划与实际状态说明。未修改仓库文件，未运行任何测试或浏览器；历史脏树没有全部重审。父代理已知的向导/布局保存锁和只读控件问题不重复列入。

发现以下3项实际问题（均P2，建议交付前修复）：

1. **布局编辑入口能直接覆盖未保存草稿，且撤销跨越保存会话。** `src/app/structures/StructurePage.tsx:38`：编辑中仍可点击“编辑布局”，无确认执行`setWidgets(data.widgets)`，刚添加/配置的组件直接消失。保存仅`setWidgets(null)`，不清undo；再次编辑并撤销会恢复上一次保存前的旧布局，违背本次草稿撤销语义。最小修复：编辑期间隐藏/禁用编辑入口，或保持已有草稿；进入新编辑会话和保存成功均清空undo，取消也保持当前清理。

2. **加载失败页的重置绕过只读和保存保护。** `src/app/structures/StructurePage.tsx:29`：没有data时的错误页总显示可执行“重置结构数据”，直接调用API，不检查readOnly，也不设置busy/locked。只读演示用户遇到首次网络加载错误或损坏快照时，可以实际清空该独立域；重置期间还可重复发起/触发加载，且workspace退出保护看不到正在保存。最小修复：只读时禁用重置，确认回调检查readOnly和锁并用try/finally维护busy，错误保留在页面，重置按钮/重试按钮统一禁用进行中的请求。

3. **缩放后的搜索定位忽略zoom，目标可被移出视口。** `src/app/structures/StructurePage.tsx:36`：搜索回调偏移`{x:280-found.x,y:100-found.y}`，但RelationCanvas按`offset + node*zoom`渲染。缩放至2倍后搜索“材料核对”（x=550），实际x=830，超出800宽视口，抽屉关闭后搜索对象仍不可见。小地图定位已正确乘zoom。最小修复：搜索定位同样用`280-found.x*zoom`和`100-found.y*zoom`（或统一定位函数），并在收起状态下展开目标。

未发现本轮声明可证实的主题CSS色值双源残留；指标分布/日期下钻使用同一tasks快照与谓词；领域写入先整体校验、持久化成功后换内存。实际状态文档明确17项领域/HTTP验证的实现者报告、8项e2e尚待统一执行及各族缺口，没有把浏览器/完整deliver提前标成通过。以上为静态结论，不能代替父代理的verify、e2e、桌面/移动截图与控制台以及deliver证据。

## 保存错误与草稿版本修复范围复核（追加）

仅检查StructurePage对应改动及新增末两项回归用例，未执行测试。两处静态修复合理，未发现本次引入的重大问题：任务抽屉内部显示保存错误且失败不清selected；taskVersion在打开任务时固定，layoutVersion/reportVersion在建立草稿时固定，刷新快照不更新这些refs，act按动作提交原版本，因而不会因切换标签自动刷新而绕过store的版本冲突检查。布局/报告取消与成功保存经各自setter清版本；任务每次重开重新捕获版本。失败保留原草稿和版本，须取消后重新建立草稿才能基于新快照提交，这是保守且安全的行为。
