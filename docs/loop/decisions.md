# 已确认架构决策（V1.0）

来源：Loop Agent 原型实践，2026-10-30；以下是执行摘要，不是原文逐字转录。DEC-001—014 的名称与边界依据 DEC-016 的兼容性表，DEC-015—016 同时依据用户确认消息。历史讨论中的建议不自动升级为用户确认。

| ID | 决策 | 执行落点 |
| --- | --- | --- |
| DEC-001 | 统一原型底座 | 保留 React/TS/Ant/Vite 与现有主题、共享容器；按实际能力矩阵选型 |
| DEC-002 | 原型与研发解耦 | 交付业务契约，不要求正式系统采用原型代码或技术栈 |
| DEC-003 | 渐进探索 | 自然语言启动，仅澄清阻断核心闭环的歧义；普通布局自主选择 |
| DEC-004 | 产品全景与核心深度 | 全景标明概念、探索、已实现；核心用户任务真正可操作 |
| DEC-005 | 轻量业务模型 | 统一对象、字段语义、关联、状态、动作、权限、约束和异常 |
| DEC-006 | 分级确认 | 高影响规则明确确认；假设、待确认不得变成已确认 |
| DEC-007 | 分范围交付 | 只交付已确认且依赖稳定的范围；其余明确排除 |
| DEC-008 | 分层审查 | 功能检查、模块闭环、跨模块与交付回归分层进行 |
| DEC-009 | 多维评价 | 检查业务、模型、交互、视觉、异常与可访问性；证据优先 |
| DEC-010 | 独立审查 | 高风险、跨模块、公共能力变化及交付前按风险触发；无独立执行者则标未完成 |
| DEC-011 | 经验沉淀 | 项目经验先为候选，脱敏、审查、获授权后才推广公共规范 |
| DEC-012 | 权威文件 | 规格定义意图，代码体现实现，测试证明符合性；工具入口只做适配 |
| DEC-013 | 双路径变更 | 低风险快速改并按任务归档；业务、状态、权限、计算、关联先确认并同步规格和回归 |
| DEC-014 | 最小研发交付契约 | 从已确认模型生成范围、规则、动作、异常、验收与版本证据，不预设数据库或接口设计 |
| DEC-015 | 正式系统验收 | 在获授权真实测试环境中验证业务、关联和体验；关键问题人工确认；无环境写未验证 |
| DEC-016 | 最小闭环与第二场景 | 先一条代表性闭环，再用不同业务结构检验通用性，不建设重型Agent平台 |

DEC-017：未确认。工单、合同、资产及供应商均不得被自动选为首个试点。现有样例只作技术与设计参考。
