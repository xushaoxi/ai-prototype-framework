# 共享执行流程

读取 AGENTS.md、README、本文、decisions.md、project-state/，再按需读 design/design-guidelines.md、能力矩阵、architecture.md 与相关 business-specs。旧计划是历史记录，不代表本次授权。原有 ai-workflow.md 的实现步骤继续适用；发生业务确认冲突时先停受影响范围并向用户澄清。

## 每次自然语言任务

1. 恢复状态：说明当前目标、已确认范围、待确认项和下一步。只问阻断问题；其他记录为假设并继续独立工作。
2. 建模：在项目业务规范维护稳定需求 ID、角色、对象与关系、字段含义/来源/校验、状态转换、动作前置条件、失败反馈和权限。金额、删除、数据范围、审批和跨模块关联默认需检查高风险。风险不清楚不得走快速路径。
3. 画出产品全景与核心任务，标记每个模块深度和依赖。概念入口不能伪装可操作成果。使用现有页面映射与共享容器，按能力矩阵承诺范围。
4. Mock：规则在 store，经 API/MSW；正常、空态、加载、失败、边界、非法转换和角色差异有确定输入/重置方式。关联 ID 引用同源对象。演示权限不是服务端安全，Mock 通过不是正式验收。
5. 验证：先领域/HTTP与规范，再浏览器操作单功能、模块闭环、跨模块回归。记录屏幕尺寸、截图、控制台、输入、步骤、预期/实际、规格与实现版本。运行既有 verify；UI变化运行 e2e；正式原型交付执行 deliver。
6. 高风险、跨模块和公共组件变化触发独立审查；交付前按风险审查确认边界与覆盖盲区。审查者以证据判断，不以作者自述通过。最多三轮修复，同问题连续两轮无改善即停止，留下阻断与人工裁决。未执行独立审查必须显式记录。
7. 交付只引用稳定已确认范围；同步 project-state 的状态、变更、待办、证据和交接。旧证据不能证明新版本，规格冲突不能靠改验收条件消除。

## 研发交付与正式验收

每次交付记录：范围及排除、确认依据、需求ID→模型→操作→验收→证据映射、原型/规格版本、关键字段与状态、角色权限、异常、Mock差异、未知项、依赖、环境条件、责任人。采用 Given/When/Then 写核心场景，不另造重复PRD。

正式验收前记录测试URL、构建版本、测试账号角色、数据准备与清理、授权范围、可用工具和环境限制。按同一业务契约验证不同研发技术栈，另查真实接口、持久化、并发、权限与跨模块关联。自动化无法覆盖的安全、业务判断、读屏或外部集成列盲区。每条状态仅可为通过/失败/阻断/未验证；关键问题由指定人工负责人最终确认。没有真实环境时止于原型交付，不能宣布正式系统通过。

## V1验证与经验

首个业务场景尚待用户确认。试点需验证核心闭环、跨工具恢复、一次低风险UI变更和一次获确认的业务变更、缺陷发现与修复回归、交付契约；真实环境可用才验正式系统。第二个不同结构场景验证复用。记录人工投入、AI成本与返工，不预报收益比例。经验候选写明问题、证据、适用边界、脱敏检查与推广批准；未经授权不回写公共母版。

## 公共模板与单项目隔离

公共：src/core、共享设计规范、工具适配、模板与脚本。单项目：project-state、业务规范、模块定义、Mock种子、项目证据及交付。现有assets/vendors和模式数据属于合成示例，不是新业务事实。新项目先使用create:project到不存在的目录，禁止复制.git、依赖、构建、release、work、.env或浏览器备份；复制整个目录后也须移除这些项目私有产物并重新初始化Git。

复制前必须人工审查业务规范、源码种子、附件、历史文档中的客户名、手机号、邮箱、合同金额、令牌与内部地址，替换为明确合成数据；扫描不能保证脱敏完整。不能将带真实客户数据的业务项目当公共模板。浏览器存储在演示工具区重置，使用独立端口/浏览器上下文防止继承旧项目数据。

项目状态重置：仅在新副本中把 project-state 替换为 templates/project-state；不要在原项目删除证据。重置后保持 DEC-001—016，清空业务确认、验收与发布状态，DEC-017仍待确认。create:project不会自动证明源码与文档已脱敏，发布模板前仍须检查。旧业务模块按 new-module 与现有生成脚本替换，不能仅重置状态便声称业务样例已删除。

## 已确认的框架参考与页面一致性边界

用户确认：2026-10-30。

- `zx-program-claude` 仅作为整体应用框架参考：左侧菜单、顶部区域、面包屑与内容区组织。具体业务菜单根据新项目任务生成，不复制其客户信息、业务数据或业务规则。
- 各类业务页面以本项目 `docs/design/design-guidelines.md` 和共享组件为准；参考项目中的列表、表单、详情等页面不能作为覆盖设计指南的依据。
- 同类查询列表页除业务字段、筛选条件、业务动作与有依据的例外外，查询区布局、查询/重置行为、按钮位置、表格样式、操作列、分页、加载/空态/错误反馈保持一致。通过共享容器和业务配置实现，不逐页复制或另写样式。
- 表单、详情及其他同类结构同样遵守对应设计规则和共享组件。特殊业务先检验组合与显式扩展点，例外记录适用范围、理由、规则ID和验收，不自行另造页面规范。
- 规范调整应在公共实现统一更新，并回归代表性使用页面；业务内容差异不能成为无依据布局差异的理由。

本条明确参考边界，不表示整体框架已迁移或页面一致性已验收。
