# 查询条件布局设计

用户已确认：常用条件直接展示，其余折叠；宽屏一行最多3个、窄屏最多2个、手机1个。按钮不计入条件；日期范围算一个，可占更多空间。隐藏条件生效时入口显示数量。

当前资产和供应商仅有关键词、类别，全部展示，不新增高级条件或折叠入口。

## 方案

已选择常用条件展示、低频条件折叠。全部展示适合当前两个条件，但不能作为未来无限堆叠的规则；独立筛选抽屉对当前简单查询增加操作成本。

## 实现选择

共享 LedgerPage 将字段和查询按钮分组。字段使用 CSS Grid；按列表内容宽度使用容器查询：不足600px一列，600px起两列，1000px起三列。最多使用当前实际字段数量的列，避免空列占位。手机视口不超过760px强制一列。按钮独立分组、按空间换行。阈值为实现选择，可根据实际字段宽度修订；不属于外部厂商统一标准。

验证两模块、桌面/指南并排/手机；按钮与Enter行为沿用QUERY-001。未来更多筛选的交互仅记录规范，尚未实现。
